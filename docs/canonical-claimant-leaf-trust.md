# Canonical dev claimant exact-leaf trust

This separate Linux shared-Chrome helper keeps direct `https://procbox.agent-trace.ts.net:3582` connections and TCP client attribution unchanged. It does not change dashboard3581, proxies, app configuration, ACLs, browser flags, or the issuing CA trust policy.

`shared_browser/claimant-leaf-trust.py preflight` validates the checked-in public claimant leaf: exact SHA256, CA:FALSE, full reviewed SAN set, TLS server purpose and current validity. It inspects the existing Chrome OS user's NSS SQL database. Optional `--probe` performs one hostname/expiry-verified TLS handshake to fixed3582 and compares exact DER, without HTTP or login. `install` requires that same live-leaf check before importing only the exact certificate under its fingerprinted managed nickname with `P,,`, then reads back DER and trust flags. Run as the shared Chrome OS user with a reviewed NSS `certutil` on PATH, never root. No database is created automatically.

NSS is OS-user-wide, not Chrome-profile- or port-specific. This leaf can be trusted wherever its existing SANs match; it cannot issue other trusted certificates. The known SANs include procbox.agent-trace.ts.net, localhost,127.0.0.1 and100.89.85.103. This is explicit peer trust, not a privacy-interstitial bypass. Chromium documents it at https://chromium.googlesource.com/chromium/src/+/refs/heads/main/docs/linux/cert_management.md . Browser qualification on the actual installed Chrome remains necessary; a successful helper run is not a completed manual browser test.

Before enrollment, review the source/public fingerprint and confirm live TLS bytes match. Root coordinates any shared-browser restart needed to reload NSS; this helper never restarts it. Do not use ignore-certificate flags. Certificate rotation fails closed and needs a new reviewed pin. Conflicting managed nicknames, altered DER or stronger trust flags reject the operation.

Verified rollback: `claimant-leaf-trust.py remove` checks the managed nickname, exact DER and P,, flags before deleting only that entry, then confirms absence. Removal permits the reviewed leaf to be expired, because removing stale trust must remain possible; install/preflight still require current validity. Removal does not contact the service unless `--probe` is explicitly requested. Other certificates, including dashboard entries, are untouched.

No live enrollment or browser changes are part of the source tests. Mock NSS tests exercise command scope/readback/conflicts; the actual bundled public certificate is validated with OpenSSL. A real disposable NSS SQL fixture additionally passed enrollment, exact readback, idempotence, conflicting trust rejection and verified removal using the existing pinned NSS tools. Actual browser acceptance remains pending; the fixture never accesses the real browser store.
